Archives 和 Chronicle 两个页面 —— 部署操作指南

这次给你做了两个 singlePage 页面，全部是赛博朋克风（和你整站统一），不是文档里那种黑白灰。

  • Archives（归档页）：替换了你原来的「时间线」归档页，URL 还是 /archive.html 不变。新的样子是「Weekly / Other」双标签页 + 按年份分组 + 每页 10 篇分页。
  • Chronicle（编年史页）：全新页面，URL 是 /chronicle.html。年份切换 + 分类切换（出游 / 书影游 / 海报墙），优先读 GitHub 上的数据 Issue，读不到就用页面里写死的备用数据。

一、改了哪些文件

直接用我给你的这 3 个文件替换仓库里的旧版本：

文件 放到哪里
enhance.js docs/enhance.js
enhance.css docs/enhance.css
config.json 仓库根目录 config.json

config.json 我只动了一处：在 singlePage 数组末尾加了 "chronicle"（archive 本来就在，没动）。你已有的其它配置一个都没删。

二、操作步骤（按顺序做）

第 1 步：替换上面 3 个文件，提交推送

把 enhance.js、enhance.css、config.json 三个文件传上去覆盖旧的，commit + push。

第 2 步：确认/创建归档页 Issue

你应该已经有一个归档页 Issue 了（标题 Archives 或别的、标签 archive）。如果有，不用动——新代码会自动接管它的渲染。

如果没有，新建一个 Issue：

  • 标题：Archives
  • 标签：archive
  • 正文：随便写一句占位就行（比如「归档」），正文内容会被新页面自动替换掉。

注意：你站里 singlePage 用的标签是 archive（单数），不是文档里的 archives。保持你原有的就好。

第 3 步：创建 Chronicle 页面 Issue

新建一个 Issue：

  • 标题：Chronicle
  • 标签：chronicle
  • 正文：复制 chronicle-page-issue.md 文件里的全部内容粘进去。

这段正文里内置了一份「备用数据」（空的框架），万一 GitHub API 读不到数据时，页面会用它兜底，不至于报错白屏。

第 4 步：创建 Chronicle 数据 Issue

再新建一个 Issue（这个是真正放编年史内容的地方）：

  • 标题：chronicle data（随便取，标签才是关键）
  • 标签：chronicle-data
  • 正文：复制 chronicle-data-issue.md 文件里的全部内容粘进去。

以后你想增删编年史的内容，只改这个 Issue 的正文就行，改完不用重新生成站点，刷新页面就能看到（因为是前端实时读 GitHub API 的）。

数据必须夹在 <!-- chronicle:data:start --> 和 <!-- chronicle:data:end --> 两行注释中间，中间是一段 JSON。

第 5 步：运行 Gmeek 全局生成

跑一次 Gmeek 的全局生成（和你平时更新博客一样的操作），让它把新的 singlePage 生成出来。

三、编年史数据怎么填

chronicle-data Issue 正文里的 JSON 结构：

  • years：有哪些年份，比如 ["2026", "2025"]。第一个是默认选中的。
  • categories：三个分类，别改 key（travel/media/posters 是写死对应渲染逻辑的），label 是显示的中文名可以改。
  • data：每个年份下，三个分类各自的内容。

**出游（travel）**每条：

{ "month": "Jan.", "city": "上海", "items": [
  { "title": "去了某展", "url": "/post/xxx.html" },
  { "title": "纯文字活动没链接" }
]}

items 里有 url 就是链接，没有就是纯文字，多个用「、」连起来。

**书影游（media）**每条：

{ "month": "Jan.",
  "books": ["《书名》"],
  "watch": ["《电影名》"],
  "shows": ["《演出名》"],
  "games": ["游戏名"] }

四个数组哪个空着就留 []，显示出来就是空格。数组项也可以写成 {"title":"x","url":"/post/x.html"} 变成链接。

**海报墙（posters）**每条：

{ "title": "海报名", "image": "图片URL", "url": "/post/xxx.html" }

image 建议用你仓库里的图（比如 https://raw.githubusercontent.com/luliy6/luliy6.github.io/main/static/img/xxx.jpg）。url 可省略（省略就不可点击）。

四、归档页 Weekly / Other 怎么分

文章会自动按标签分到两个标签页：

  • Weekly：文章标签里有这些任意一个 → Weekly、weekly、周记、周报、二十四节气
  • Other：不是 Weekly、也不是系统页的，都进 Other
  • 不会出现的：标签是 archive/chronicle/chronicle-data/about/book/favorites/stock/link/gallery 这些系统页，会被自动排除

归档页的文章列表是自动跟着你的 GitHub Issues 更新的，你正常发文章（带标签）就会自动出现，不用手动维护列表。

五、验收清单

部署后逐项检查：

Archives（/archive.html）

  • 页面右上角有「Weekly | Other」两个标签，中间有竖线分隔
  • 当前标签是高亮的（白色 + 发光）
  • 点标签切换内容，页面不刷新
  • 文章按年份分组，年份是青色发光大字
  • 每行左边灰色日期、右边文章标题，鼠标悬停会高亮 + 右移
  • 点标题能跳到对应文章
  • 超过 10 篇时底部出现「< Page 1 of N >」分页
  • 点分页换内容、不刷新页面
  • 刷新页面后，还记得上次选的是 Weekly 还是 Other

Chronicle（/chronicle.html）

  • 右上角有年份切换（2026 | 2025...），当前年份下面有青色短下划线
  • 下面有分类切换（出游 / 书影游 / 海报墙），当前分类下面有品红下划线
  • 切年份、切分类都不刷新页面
  • 出游是 3 列表格（月份 / 城市 / 活动）
  • 书影游是 5 列表格（月份 / 读书 / 观影 / 演出 / 游戏）
  • 海报墙是网格（桌面 7 列、平板 5 列、手机 3 列），图片 2:3 比例
  • 海报鼠标悬停时图片轻微放大 + 底部浮出标题
  • 改 chronicle-data Issue 的内容后，刷新页面能看到更新（不用重新生成站点）
  • 刷新页面后，还记得上次选的年份和分类

两个页面共通

  • 整体是赛博朋克霓虹风，和你站里其它页面风格一致
  • 手机上表格能横向滑动，不会撑破屏幕
  • 数据读取失败时显示友好的错误提示，不会白屏

六、小提示

  • 编年史的 repo 默认是 luliy6/luliy6.github.io，已经写死在代码里了，不用配置。如果以后换仓库，在网页 <head> 里加一句 <script>window.LULIY_CHRONICLE_REPO='你的用户名/仓库名';</script> 就能覆盖。
  • GitHub API 有调用频率限制（未登录每小时 60 次），正常浏览完全够用。万一触发限制，页面会自动回退到 Chronicle Issue 里内置的备用数据。
